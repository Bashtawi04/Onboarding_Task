### Architecture

`data/policy_register.csv` -> allowlisted current docs -> `onboarding/documents.py` extracts PDFs/Markdown -> character chunks -> `build_index.py` creates local JSON vector index with Azure embeddings -> `ask.py` embeds question, retrieves top 5 chunks, provides relevant full-page text + authorized structured HR context -> Azure chat response with citations -> JSONL audit.

`onboarding/records.py` keeps employee and task CSVs **outside** document embeddings, checks simulated identity/manager relations before retrieval, sorts tasks, computes conditional first pay and working-day IT dates.

### Important scope and limits

- **Never send an API key or `.env` file in chat.** Keys are prompted privately; batch evaluation supports `AZURE_OPENAI_API_KEY` environment variable as an alternative.
- Fixed scenario date `2026-10-16`; optionally use `--today YYYY-MM-DD` for ad hoc tests; do not mix dates in official evaluation.
- Citation labels are checked for existence, **not for semantic claim support**. Human review of factual accuracy remains necessary.
- Absence of relevant documents is handled through model instructions, not mathematically proven. Never present this as production-grade refusal verification.
- Simulated `--asker` and `--target` inputs **are not authentication**. Real SSO identity binding, redaction, access enforcement, encryption and security testing are required for production.
- No React/FastAPI UI is needed for the assignment; no tickets, email or HR changes are actually performed.
- The vector index stores full page text; it is a lightweight local demo, not a scalable database.
- Note any first-pay date is conditional on a verified IBAN.
- For the official chunk-size experiment: `python -m onboarding prepare --size 400 --overlap 100` and `python build_index.py --size 400`, then run evaluation. Repeat with 800. Each index build costs Azure embedding calls; back up reports before rerunning since the report filename is the same. Start with the existing 700 index.
